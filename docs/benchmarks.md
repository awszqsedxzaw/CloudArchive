# 压缩与转换基准

2026-10-13，在同一台 Windows 机器上用 JDK 21、128 MiB Java 堆测试。旧实现为提交 `63b1c53`，新实现为 `CAMD v2`。单位 MB 为 1,000,000 字节，MiB 为 1,048,576 字节。

## 输入与方法

用户提供的输入位于 `C:\everything\workspace\Projects\test`：

| 输入 | 原始大小 | 提供的旧投影大小 |
| --- | ---: | ---: |
| `GTMC.zip` | 181,495,472 字节 | 182,615,775 字节 |
| `GTMC` | 199,162,351 字节 | 188,223,118 字节 |

目录包含 4,826 个文件和 677 个子目录，包括隐藏的 `.git`、`.idea` 和 `node_modules`。其中约 97.47 MB 为无扩展名文件（大量 Git 对象），34.59 MB 为 GIF，31.05 MB 为 PNG，18.61 MB 为 Git pack，7.80 MB 为 JavaScript。

每个进程先用 1 MiB 随机文件预热，再执行三次完整打包和还原。耗时只覆盖编解码器调用，不含 Gradle/JVM 启动，也不含最终比较。每次都比较完整目录结构、节点类型和每个文件的 `Files.mismatch`；六次旧版和六次新版还原全部一致。测试输出位于项目忽略的 `build/`，原始输入和提供的两个投影未修改。

投影中的创建时间不同，压缩后的大小有几个字节波动。与提供的旧投影相比，ZIP 减少 4.83%，目录减少 9.80%。以耗时中位数比较，ZIP 打包约快 1.99 倍，目录打包约快 2.17 倍；还原耗时分别减少约 19.4% 和 19.5%。

目录去重后逻辑数据为 198,346,890 字节，节省 815,461 字节。Zstandard/RAW 块合计为 167,962,807 字节；最终投影还包含 Base64/NBT、元数据和外层 gzip。这批数据中的重复文件较少，体积收益主要来自分块压缩。

## 书页编码比较

取 `GTMC.zip` 的前 16 MiB，实际调用 `DataOutputStream.writeUTF` 写书页，接 gzip。每项执行三轮，舍弃首轮，以下为后两轮平均耗时。只比较编码加 gzip，不代表完整打包耗时。

| 编码 | gzip 级别 | 压缩字节数 | 编码加 gzip 秒数 |
| --- | ---: | ---: | ---: |
| Base64（无填充 URL-safe） | 1 | 17,296,273 | 0.930 |
| 每字节映射到 U+0100..U+01FF | 1 | 21,427,038 | 0.983 |
| 每 15 位映射到 U+3000..U+AFFF | 1 | 20,150,451 | 0.997 |
| Base64（无填充 URL-safe） | 6 | 16,929,926 | 1.027 |
| 每字节映射到 U+0100..U+01FF | 6 | 21,198,203 | 2.576 |
| 每 15 位映射到 U+3000..U+AFFF | 6 | 20,210,397 | 1.278 |

NBT 字符串用 modified UTF-8；多字节字符的开销不能按 Java 字符数忽略。15 位字符映射还会超过 NBT 字符串的 65,535 字节上限，因此实验将每页输入限制为 40,957 字节。两种字符映射只用于编码实验，未作为归档格式实现。不能把原始字节数组当作原生书页。

在同一样本上，Zstandard 级别 6 将 16 MiB 压到 16,704,157 字节，压缩平均约 0.103 秒；Deflate 级别 6 得到 16,754,492 字节，平均约 0.475 秒。最终保留 Base64，以 Zstandard 独立块改善书内数据容量，并保持外层 gzip 级别 6 的体积，通过并行生成 gzip 成员提高打包速度。

## 复现

以下任务可以测试任何文件或目录，不依赖已删除的旧格式读取器：

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'

.\gradlew.bat benchmarkFileCodec "--args='C:\everything\workspace\Projects\test\GTMC.zip' 'build\bench-zip-new' 'C:\everything\workspace\Projects\test\GTMC.zip.litematic' 3"
.\gradlew.bat benchmarkFileCodec "--args='C:\everything\workspace\Projects\test\GTMC' 'build\bench-tree-new' 'C:\everything\workspace\Projects\test\GTMC.litematic' 3"
.\gradlew.bat benchmarkPageEncoding "--args='C:\everything\workspace\Projects\test\GTMC.zip'"
```

三个参数依次为输入、新的测试输出目录、只用于获取基准大小的旧投影；可选第四个参数为运行次数。每次复现使用新的输出目录。旧投影不会被读取或还原，所有输入也不会被覆盖。运行三轮完整测试需预留数 GB 磁盘空间。

此记录验证离线投影格式、标准 gzip/NBT 解码和文件还原；没有替代游戏内粘贴、服务器同步和再导出的实测。随机数据、已经充分压缩的数据不保证缩小，实际耗时取决于 CPU、磁盘和文件数量。
