# CloudArchive 当前归档格式

本文描述当前唯一支持的格式。旧版本格式不在读取器中实现，也不作为兼容目标。格式面向 Minecraft 1.20.1 的 Litematica 投影。

## 投影布局

投影使用一个 `FileStorage` 区域，尺寸为 `N x 1 x 1`，木桶坐标为 `(0, 0, 0)` 到 `(N-1, 0, 0)`。

- `x=0`：唯一的元数据木桶，书标题为 `Metadata`。
- `x>=1`：数据木桶，书标题为 `Data`，只包含压缩数据块或 RAW 字节。

元数据木桶最多 27 本书。空文件或空目录树只有元数据木桶，不包含数据书。每个数据木桶最多 27 本书。非末尾书必须写满 100 页，末尾书也只有最后一页可以不满。

Litematica 外层为 gzip NBT。写入器将 NBT 分为最多 1 MiB 的片段，并行生成 gzip level 6 成员，按顺序拼接；整个结果是标准 gzip 流，Minecraft 的 `GZIPInputStream` 支持拼接成员。小投影只有一个成员。当前固定使用：

```text
Version = 6
SubVersion = 1
MinecraftDataVersion = 3465
```

调色板的 0 号为 `minecraft:air`，1 号为 `minecraft:barrel`。所有木桶的实体坐标和 X 顺序必须保留。NBT compound 字段顺序不重要。

## 原生书 NBT

书物品只允许下列原生字段：

```text
{
  id: "minecraft:written_book",
  Count: 1b,
  Slot: 0..26b,
  tag: {
    author: "CloudArchive",
    title: "Metadata" | "Data",
    generation: 0,
    resolved: true,
    pages: [ "URL-safe unpadded Base64", ... ]
  }
}
```

不允许任何额外 item 或 `tag` 字段。每本书 1 到 100 页；除最后一页外，每页解码后必须是 24,573 字节。页面顺序是数据顺序，书的地址由木桶 X 和 `Slot` 决定：

```text
metadata_book_index = Slot
data_book_index = (barrel_x - 1) * 27 + Slot
```

Base64 页按无填充 URL-safe 编码。每页最多 32,764 个 ASCII 字符，对应 24,573 字节。数据书不能通过普通书界面编辑。

## 元数据文件

将元数据木桶中的书按 `Slot` 拼接后，得到一个 big-endian 二进制文件。整数使用 Java `DataInput`/`DataOutput` 的大端序。文件包含 100 字节固定头、归档名称、节点记录和压缩块表。仅支持版本 2。

### 固定头

| 偏移 | 长度 | 字段 |
| ---: | ---: | --- |
| 0 | 4 | magic，ASCII `CAMD`，值 `0x43414D44` |
| 4 | 2 | version，当前为 2 |
| 6 | 2 | feature flags，当前为 0 |
| 8 | 1 | kind，`0=FILE`，`1=TREE` |
| 9 | 3 | 保留，必须为 0 |
| 12 | 8 | generation，当前写入 0，读取必须非负 |
| 20 | 8 | next_id，必须大于所有节点 ID |
| 28 | 4 | node_count |
| 32 | 8 | metadata_length，必须等于元数据文件长度 |
| 40 | 8 | data_length，去重后、解压后的逻辑数据总长度 |
| 48 | 4 | data_book_count，根据 stored_length 计算 |
| 52 | 4 | archive_name_length |
| 56 | 32 | 逻辑数据整体 SHA-256 |
| 88 | 8 | stored_length，数据书解码后的存储总长度 |
| 96 | 4 | block_count |
| 100 | 可变 | UTF-8 归档名称，随后是节点记录、压缩块表 |

元数据书拼接后的长度必须不超过一个木桶，即 66,347,100 字节；索引大小变化不会影响数据区地址，因为数据独立存放。

### 节点记录

每条记录依次为：

| 长度 | 字段 |
| ---: | --- |
| 1 | 类型，`0=directory`，`1=file` |
| 8 | 节点 ID，正数且唯一 |
| 8 | parent ID，0 表示隐式根目录 |
| 4 | 名称 UTF-8 字节数，1 到 1,024 |
| 可变 | 单个路径组件名称 |

文件节点随后追加：

| 长度 | 字段 |
| ---: | --- |
| 8 | 文件长度 |
| 32 | 文件 SHA-256 |
| 4 | extent 数量 |
| 16 | 每个 extent：`offset`、`length` |

extent 偏移从解压后的逻辑数据文件的字节 0 开始，不包含任何元数据头，也不是压缩数据的物理偏移。一个文件可以拥有多个不连续区间；区间长度之和必须等于文件长度，区间必须落在逻辑数据范围内。当前打包器为非空文件写入一个连续区间，相同长度和 SHA-256 的文件复用同一个区间；读取器支持预留的多个区间。

目录节点占 `21 + 名称字节数` 字节，空文件占 `65 + 名称字节数` 字节，每个 extent 另占 16 字节。哈希直接存 32 字节，不存 64 字符十六进制文本。根目录隐式使用 ID 0，不占节点记录；名称和区间之外不添加填充、重复完整路径或页头。

当前打包器按根相对路径排序、从 1 分配 ID，唯一文件数据连续写入且不对齐。读取器使用记录中的 ID；区间按记录顺序拼成逻辑文件，逻辑偏移无需递增，允许复用区间及数据区中的未使用字节。重新打包不是已有归档的更新操作。

父目录必须先于子节点出现。名称不得为空、`.`、`..`、包含路径分隔符、控制字符、Windows 非法字符、保留设备名，或以空格/点结尾。节点、区间、计数、UTF-8、哈希、尾随字节和所有长度都会严格校验。

`FILE` 归档必须恰好有一个根文件节点，文件长度必须等于逻辑数据长度。`TREE` 归档允许目录、空文件和空目录。

### 压缩块表

节点记录之后紧接 `block_count` 条记录，每条恰好 9 字节：

| 长度 | 字段 |
| ---: | --- |
| 1 | codec：`0=RAW`、`1=Zstandard` |
| 4 | raw_length：1 到 4,194,304 |
| 4 | stored_length：正数，不超过 raw_length |

RAW 块必须满足 `stored_length == raw_length`；Zstandard 块必须满足 `stored_length < raw_length`。每个 Zstandard 块是独立、无外部字典的标准帧，写入器使用级别 6。块没有 CloudArchive 数据头，也没有对齐填充；数据木桶只拼接各块的存储字节。全部类型和长度描述均位于元数据木桶。

块的逻辑起点为前面块的 `raw_length` 之和，存储起点为前面块的 `stored_length` 之和，无需重复存储偏移。两种长度之和必须分别等于固定头的 `data_length` 和 `stored_length`；未知 codec、越界长度、解压长度不匹配或尾随字节均拒绝。整体逻辑数据 SHA-256 与每个文件 SHA-256 用于校验。

文件之间不补齐块、页、书或木桶。块可跨文件边界；分块使后续实现可以通过追加块和重定向文件 extent 修改内容，不要求把整个归档压成单一不可拆分流。目前没有修改命令。

## 写入与读取保证

当前命令生成不可变快照，不实现更新、删除、追加或原地修改。稳定 ID、`next_id`、`generation` 和显式 extent 仅为后续格式扩展预留，不表示已有日志或事务能力。

打包时会重新读取并校验源文件的大小、时间、文件身份和 SHA-256，包括只复用区间的重复文件。复制唯一内容时同时计算整体哈希。还原时先把元数据和存储数据写入临时文件，按块解压并校验整体 SHA-256，再校验每个文件；树还原在私有目录中完成，成功后才移动到目标位置。目标已存在、书缺失、书重复、槽位不连续、坐标移动、数据损坏或自定义 NBT 字段都会使操作失败。

书籍列表和 compound 字段的物理排列顺序可以改变，因为读取器按 `Slot` 和坐标定位。库存槽位与木桶坐标本身是地址，重新保存投影时必须保留。
